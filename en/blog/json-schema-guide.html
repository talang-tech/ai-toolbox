JSON Schema Guide: From Zero to Data Validation

2026-06-17 · AI Toolbox

When developing APIs, managing configuration files, or integrating data systems, you often need to ensure JSON data follows specific structures and constraints. JSON Schema is the standard solution—a declarative JSON description language that lets you describe data rules using JSON itself.

What is JSON Schema?

JSON Schema is a specification for describing JSON data formats. Think of it as a "data blue print" that defines which fields a JSON object should have, their types, which are required, acceptable value formats, and ranges. You can then use a validator tool to automatically check if your data follows the "blue print."

JSON Schema is self-describing: written in JSON to validate JSON. The current mainstream version is Draft-07, supported by many online validators.

Quick Start: Your First Schema

Suppose your user registration API expects this JSON:

{
  "name": "Alice",
  "email": "alice@example.com",
  "age": 28
}

Describe it with JSON Schema:

{
  "type": "object",
  "required": ["name", "email", "age"],
  "properties": {
    "name": { "type": "string" },
    "email": { "type": "string", "format": "email" },
    "age": { "type": "integer", "minimum": 0, "maximum": 150 }
  }
}

Basic Validation Rules

Type Check (type)

Seven supported types: string, number, integer, object, array, boolean, null. Note that integer and number are distinct—integer is a subset of number.

Required Fields (required)

{
  "type": "object",
  "required": ["id", "created_at"]
}

String Constraints (pattern / minLength / maxLength / format)

{
  "type": "object",
  "properties": {
    "phone": { "type": "string", "pattern": "^1[3-9]\\d{9}$" },
    "website": { "type": "string", "format": "uri" },
    "uuid": { "type": "string", "format": "uuid" }
  }
}

Supported formats include email, uri, date-time, uuid, ipv4, hostname.

Numeric Constraints (minimum / maximum / multipleOf)

{
  "type": "object",
  "properties": {
    "price": { "type": "number", "minimum": 0.01, "exclusiveMinimum": true },
    "quantity": { "type": "integer", "minimum": 1, "maximum": 999 },
    "batch": { "type": "integer", "multipleOf": 10 }
  }
}

Enumeration (enum)

{
  "type": "object",
  "properties": {
    "status": { "type": "string", "enum": ["active", "inactive", "suspended"] }
  }
}

Array Validation

{
  "type": "array",
  "items": { "type": "string" },
  "minItems": 1,
  "maxItems": 10,
  "uniqueItems": true
}

Combinators: allOf / anyOf / oneOf / not

  • allOf: all sub-schemas must pass
  • anyOf: at least one sub-schema must pass
  • oneOf: exactly one sub-schema must pass
  • not: data must NOT match the sub-schema

if-then-else Conditional Validation

{
  "type": "object",
  "properties": { "type": { "enum": ["individual", "company"] } },
  "if": { "properties": { "type": { "const": "company" } } },
  "then": { "required": ["tax_id"] },
  "else": { "required": ["personal_id"] }
}

Real-World Use Cases

1. API Response Validation

Validate API responses against a contract during frontend-backend integration. Use the online JSON Schema Validator without installing anything.

2. Config File Verification

Write schemas for your JSON configuration files and validate them at startup.

3. Data Quality Checks

Validate each batch of data in a pipeline to catch malformed records early.
