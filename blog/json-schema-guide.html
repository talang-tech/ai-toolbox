JSON Schema 入门：从零理解数据校验规范

2026-06-17 · AI 工具盒子

在 API 开发、配置文件管理、数据集成等场景中，我们经常需要确保 JSON 数据符合特定的结构和约束。JSON Schema 正是为了解决这个问题而生——一种声明式的 JSON 数据描述语言，让你用 JSON 本身来描述 JSON 数据的规则。

什么是 JSON Schema？

JSON Schema 是一个描述 JSON 数据格式的规范。它像一套「数据说明书」，定义一个 JSON 对象应该包含哪些字段、每个字段的类型、哪些字段必填、值的格式和范围等。然后你就可以用工具自动检查数据是否「符合说明书」。

JSON Schema 是 自描述的：用 JSON 格式写规则，校验 JSON 数据。当前主流版本是 Draft-07，许多在线工具和服务（如 JSON Schema 校验器）都支持它。

快速上手：第一个 Schema

假设我们有一个用户注册 API，期望接收这样的 JSON：

{
  "name": "张三",
  "email": "zhangsan@example.com",
  "age": 28
}

用 JSON Schema 描述它：

{
  "type": "object",
  "required": ["name", "email", "age"],
  "properties": {
    "name": { "type": "string" },
    "email": { "type": "string", "format": "email" },
    "age": { "type": "integer", "minimum": 0, "maximum": 150 }
  }
}

这个 Schema 规定了：数据必须是对象 (object)；三个字段必填 (required)；name 是字符串；email 必须是合法的 email 格式；age 是整数且范围 0-150。

基础校验规则详解

类型检查 (type)

type 是最基础也最常用的校验规则，支持七种类型：string、number、integer、object、array、boolean、null。JSON Schema 把 integer 和 number 分开对待——整型是 number 的子集。

必填字段 (required)

required 是一个字符串数组，列出必须在数据中出现的字段名：

{
  "type": "object",
  "required": ["id", "created_at"]
}

字符串约束 (pattern / minLength / maxLength / format)

JSON Schema 支持多种字符串校验方式：

{
  "type": "object",
  "properties": {
    "phone": { "type": "string", "pattern": "^1[3-9]\\d{9}$" },
    "bio": { "type": "string", "minLength": 10, "maxLength": 500 },
    "website": { "type": "string", "format": "uri" },
    "uuid": { "type": "string", "format": "uuid" }
  }
}

format 支持 email、uri、date-time、uuid、ipv4、hostname 等常用格式。

数值约束 (minimum / maximum / multipleOf)

{
  "type": "object",
  "properties": {
    "price": { "type": "number", "minimum": 0.01, "exclusiveMinimum": true },
    "quantity": { "type": "integer", "minimum": 1, "maximum": 999 },
    "batch": { "type": "integer", "multipleOf": 10 }
  }
}

枚举 (enum)

限制值必须在枚举列表中：

{
  "type": "object",
  "properties": {
    "status": { "type": "string", "enum": ["active", "inactive", "suspended"] }
  }
}

数组校验

JSON Schema 对数组的校验非常灵活，可以分别校验每个元素：

{
  "type": "array",
  "items": { "type": "string" },
  "minItems": 1,
  "maxItems": 10,
  "uniqueItems": true
}

也可以使用「元组」形式：

{
  "type": "array",
  "items": [
    { "type": "string" },
    { "type": "integer" },
    { "type": "boolean" }
  ],
  "additionalItems": false
}

对象高级校验

additionalProperties

默认情况下，JSON 对象可以包含 Schema 未声明的额外字段。用 additionalProperties: false 可以禁止：

{
  "type": "object",
  "properties": {
    "name": { "type": "string" },
    "email": { "type": "string", "format": "email" }
  },
  "additionalProperties": false
}

propertyNames

用正则限制属性名格式：

{
  "type": "object",
  "propertyNames": { "pattern": "^[a-z_][a-z0-9_]*$" }
}

组合校验：allOf / anyOf / oneOf / not

JSON Schema 支持逻辑组合多个子 Schema：

  • allOf：子 Schema 全部通过才算通过
  • anyOf：至少一个子 Schema 通过
  • oneOf：恰好一个子 Schema 通过
  • not：不能匹配子 Schema

举例：用户可以是普通用户或 VIP，但只能是一种：

{
  "oneOf": [
    { "properties": { "role": { "const": "user" } }, "required": ["role"] },
    { "properties": { "role": { "const": "vip" }, "vip_level": { "type": "integer" } }, "required": ["role", "vip_level"] }
  ]
}

if-then-else 条件校验

JSON Schema Draft-07 最强大的新特性之一：

{
  "type": "object",
  "properties": {
    "type": { "enum": ["individual", "company"] },
    "tax_id": { "type": "string" },
    "personal_id": { "type": "string" }
  },
  "if": { "properties": { "type": { "const": "company" } } },
  "then": { "required": ["tax_id"] },
  "else": { "required": ["personal_id"] }
}

实际应用场景

1. API 响应校验

前后端联调时，用 JSON Schema 校验 API 响应是否「遵守合约」，快速定位少字段、类型不对、格式非法等问题。配合 在线 JSON Schema 校验器 可以不用安装任何工具。

2. 配置文件验证

给项目中的 JSON 配置文件（如 config.json）编写 Schema，在启动时自动验证配置完整性。

3. 表单规则描述

用 JSON Schema 描述表单校验规则，前端和后端共用同一套 Schema，避免校验逻辑不一致。

4. 数据质量检查

数据管道中对每批数据做 Schema 校验，确保字段格式符合预期，及早拦截脏数据。

在线验证

无需安装，打开 JSON Schema 校验器 即可在浏览器中体验。粘贴 Schema 和数据，一键校验，所有数据留在本地，适合处理敏感业务数据。
